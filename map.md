Проект уже рабочий по структуре, но главные риски сейчас — WebSocket-масштабирование, production-конфигурация и отсутствие защиты от деградации при сбоях.

### Критично исправить

1. **Возвратить `base: "/geomap/"` в Vite**

Сейчас приложение отдаётся nginx по `/geomap/`, но в изменённом [vite.config.ts](./webapp/vite.config.ts:5) `base` удалён. В production пути к JS/CSS будут формироваться как `/assets/...` вместо `/geomap/assets/...`.

2. **Заменить InMemoryChannelLayer на Redis**

В [settings.py](./backend/geomap_api/settings.py:66) используется `InMemoryChannelLayer`. Он не работает между несколькими процессами/контейнерами и теряет события при перезапуске.

Рекомендуется:

- Redis;
- `channels-redis`;
- `REDIS_URL` через `.env`;
- уведомления через `transaction.on_commit()` в [signals.py](./backend/points/signals.py:9).

3. **Оптимизировать WebSocket**

Сейчас каждое изменение:

- рассылает полный список точек всем клиентам;
- выполняет отдельный запрос к БД для каждого соединения;
- пересоздаёт все маркеры на frontend.

Это находится в [consumers.py](./backend/points/consumers.py:24).

Лучше передавать события `created/updated/deleted` или использовать HTTP-загрузку по viewport с WebSocket только для идентификаторов изменений.

4. **Добавить переподключение WebSocket**

В [usePointsSocket.ts](./webapp/src/map/usePointsSocket.ts:31) после разрыва соединение не восстанавливается. После краткого сбоя сети карта останется устаревшей до перезагрузки приложения.

Нужны:

- exponential backoff;
- heartbeat/ping;
- обработка некорректного JSON;
- ограничение количества попыток;
- повторная авторизация при `401/403`.

5. **Исправить утечку ресурсов маркеров**

В [pointMarkers.ts](./webapp/src/map/pointMarkers.ts:14) для каждого маркера создаётся React root, но при удалении маркера `root.unmount()` не вызывается. При частых обновлениях это может привести к росту памяти.

Для большого числа точек лучше перейти на:

- GeoJSON source/layers MapLibre;
- кластеризацию;
- обновление только изменённых маркеров.

### Производительность backend

6. **Убрать N+1-запросы**

В `PointViewSet` нет базового `select_related('point_type')`, хотя сериализатор обращается к `point_type.name` и `point_type.icon_name`.

Добавить в [views.py](./backend/points/views.py:81):

```python
Point.objects.filter(is_active=True).select_related("point_type")
```

7. **Кэшировать MinIO-клиент и presigned URL**

В [point.py](./backend/points/models/point.py:57) новый MinIO-клиент создаётся для каждой фотографии. При 100 точках это лишние объекты и вычисления.

Нужно:

- кэшировать MinIO client;
- генерировать URL централизованно;
- продумать обновление истёкших ссылок;
- удалять старые файлы при замене фотографии.

8. **Ограничить выдачу карты**

WebSocket сейчас отправляет все точки. Для роста данных нужны:

- bounding box по текущей области карты;
- пагинация;
- фильтрация по типу;
- кластеризация;
- индексы под реальные запросы.

9. **Добавить валидацию координат и файлов**

В [models/point.py](./backend/points/models/point.py:25) координаты — обычные `FloatField` без диапазонов.

Нужны ограничения:

- latitude: `-90..90`;
- longitude: `-180..180`;
- максимальный размер фото;
- проверка MIME-типа;
- проверка реального содержимого изображения;
- ограничение разрешения.

Сейчас бот читает весь файл фотографии в память в [bot.py](./bot/bot.py:163).

### Надёжность

10. **Добавить retry и общий HTTP-клиент**

В [api_client.py](./bot/api_client.py:11) новый `httpx.AsyncClient` создаётся на каждый запрос.

Лучше использовать один клиент на весь жизненный цикл бота с:

- connection pooling;
- раздельными timeout;
- retry для временных ошибок;
- обработкой `502/503/504`;
- ограничением параллельных запросов.

11. **Перевести FSM бота с MemoryStorage**

[bot.py](./bot/bot.py:20) использует `MemoryStorage`. При рестарте бот теряет все незавершённые сценарии добавления точки.

Для production лучше Redis storage.

12. **Сделать регистрацию идемпотентной**

В [views.py](./backend/points/views.py:29) повторная регистрация пользователя возвращает `409`, хотя функция называется login/register. Повторный запуск сценария может ошибочно восприниматься как сбой.

Лучше возвращать существующий профиль и токен либо явно разделить регистрацию и авторизацию.

13. **Проверять будущие `auth_date`**

В [auth.py](./backend/points/auth.py:33) проверяется только слишком старое значение. Будущая дата фактически принимается.

Добавить допустимый clock skew, например 60 секунд.

### Безопасность и production

14. В [settings.py](./backend/geomap_api/settings.py:153) используется:

```python
CORS_ALLOW_ALL_ORIGINS = True
```

Нужно заменить на список доверенных доменов.

15. Production должен завершаться с ошибкой при:

- `DEBUG=true`;
- стандартном `SECRET_KEY`;
- стандартном `BOT_API_KEY`;
- пустом `ALLOWED_HOSTS`.

Сейчас безопасные значения не проверяются.

16. Ограничить открытые порты в [docker-compose.yml](./docker-compose.yml:44):

- MinIO не должен быть доступен напрямую наружу;
- backend должен быть доступен только nginx;
- webapp также лучше не публиковать напрямую.

17. Добавить healthcheck для backend, bot, webapp и nginx. Сейчас `depends_on` контролирует в основном порядок запуска, но не готовность приложения.

18. Добавить `X-Forwarded-For`, `X-Forwarded-Proto`, лимит размера тела запроса и cache headers в [nginx.conf](./nginx/nginx.conf:7).

### Frontend

19. Удалить неиспользуемую зависимость `mapbox-gl` из [package.json](./webapp/package.json:14), если она действительно нигде не используется.

20. HTML в popup лучше собирать через DOM-элементы, а не строковой конкатенацией в [pointMarkers.ts](./webapp/src/map/pointMarkers.ts:48). Сейчас URL изображения и текстовые поля требуют более строгой защиты.

21. В боте нужно экранировать пользовательские `title` и `description` перед отправкой с `parse_mode="HTML"` в [bot.py](./bot/bot.py:234).

### Текущий статус проверок

- Python-файлы синтаксически корректны.
- `docker compose config` проходит.
- Frontend-сборка падает из-за отсутствующего `lucide-react` в локальном `node_modules`; после чистого `npm ci` это нужно проверить повторно.
- Django `check` не запускается из-за отсутствующего `channels` в локальном виртуальном окружении.
- Автоматических тестов в проекте практически нет.

Приоритетный порядок: вернуть Vite `base`, Redis для Channels, reconnect WebSocket, оптимизировать выдачу точек и маркеры, затем добавить healthchecks, retry, валидацию файлов и production-безопасность.
